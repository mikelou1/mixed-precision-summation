But computers do not keep every digit

To stay fast, each number gets a fixed amount of space, a fixed digit budget. The three common sizes come from the IEEE 754 standard: fp64 keeps about 16 digits, fp32 about 7, fp16 about 3.

Watch what happens when each one tries to store 0.1. One tenth needs endless digits in binary, so each format keeps only the digits its budget allows. The black digits are what it holds. Everything in gray is drift, the precision that format does not have:

fp16 holds about 3 digits, so it stores something close to but not quite 0.1. fp32 holds about 7, fp64 about 16. None is exact, since one tenth has no exact binary form, but a bigger budget keeps more real digits before the drift starts. A tiny error on one number, but it builds up across many.

Bigger size costs more

More digits means more work for the chip. Roughly, one fp32 add costs as much as two fp16 adds, and one fp64 add costs as much as eight.

fp16cost 1  cheapest, fewest digits
fp32cost 2  2× an fp16 add
fp64cost 8  8× an fp16 add

So you want the answer accurate and cheap. Those pull against each other. The score rolls both into one number:

score = 100 × how accurate × how cheap

how accurate: 1.0 if you hit the true total, lower as you drift off.
how cheap: more adds for less cost scores higher. All-fp64 is accurate but its cost drags this down.
